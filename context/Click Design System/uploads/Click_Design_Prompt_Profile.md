# Click - Profile (one content model, three surfaces)

**The decision (v3.1): ONE profile, shown two ways - the page and the modal are the SAME tight layout.** There is NO separate "profile preview" page. Same contained block, same styling, same spacing; only the chrome differs (page has "Edit profile"; modal has a "click with [name]" footer + close). The DISPLAY never contains controls - editing/settings live on their own page.
- **Your own profile (Mode A)** - a PAGE that renders the ONE shared profile block, centered and contained (~600-680px - not a sprawling wide page), plus ONE "Edit profile" button. NO inline toggles, NO privacy boxes, NO completion machinery.
- **Viewing someone (Mode B)** - the SAME shared block inside a CENTERED MODAL (overlay), read-only public subset + a "click with [name]" sticky footer. This modal is the single thing opened by "View profile" on a people card (ClickMechanic §F) AND by tapping an attendee on Event Detail - one component, can't drift. It is an overlay, NOT a new page.
- **Profile edit (Mode C)** - a page that lives UNDER **Settings** (the "Edit profile" section; spec `Click_Design_Prompt_ProfileEdit.md`, hub `Click_Design_Prompt_Settings.md`). Edit profile holds profile CONTENT; the "Open to dating" toggle, dating preferences, and "Show me in event attendee lists" live in Settings -> Privacy & visibility. NONE of these live on the display.
